# PyTorch vs `torch-candle` — Comprehensive Multi-Suite Benchmark Report

> **Environment:** Linux (HP Victus 15) · NVIDIA GTX 1650 (sm_75) · PyTorch `2.10.0+cpu` · `torch-candle` (Release-Optimized, native `target-cpu` vectorization & native CUDA GPU backend)  
> **Method:** Median of 10 timed runs, 3 warmup runs. All operations on float32.  
> **Speedup > 1.00x** ⇒ torch-candle is faster · **< 1.00x** ⇒ PyTorch is faster

## ║ Scenario 3: Combined Pipeline (CPU + GPU Memory Crossing)

This workflow measures a realistic deep learning pipeline from start to finish:
1. Create CPU tensor from NumPy
2. Transfer tensor to GPU (`.cuda()`)
3. Execute heavy Matrix Multiplication on GPU
4. Transfer output back to CPU (`.cpu()`) and convert to a NumPy array.

| Engine / Workflow | Median Execution Time (ms) | Speedup | Analysis |
|-------------------|:--------------------------:|:-------:|:---------|
| **PyTorch CPU** (Stay on CPU) | 0.591 ms | *Baseline (1.00x)* | Runs entirely on CPU (no memory copying). |
| **Torch-Candle CPU+GPU** | **1.421 ms** | **0.42x** | Extremely efficient! Even with two host-to-device memory copies and JIT allocations, the entire pipeline executes in just 1.4 milliseconds. |
