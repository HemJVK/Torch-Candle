Self-Healing Autograd Engine (SHA)

Numerical instability (e.g. division by zero, floating point overflow) in traditional deep learning engines permanently corrupts model weights with NaN or Inf values. Once weights are corrupted, training terminates or must be restarted from an older checkpoint.

SHA intercepts anomalous gradients at an element-wise level during the backward pass. Instead of propagating the corruption, it leverages parameter-specific history to reconstruct a healthy gradient estimate on-the-fly using a dynamic Exponential Moving Average:

gt = β · gt-1 + (1 - β) · gcurr

Core Parameters & Factors

  • Smoothing Factor (β): Usually set to 0.9. High values rely on gradient history; low values lean on new steps.
  • Anomaly Level: Scans for NaN/Inf element-wise to avoid resetting healthy parameter gradients.
  • Fallback Safe Mode: Reverts to zero if an anomaly is hit on step 0 before history exists.

Auto-Device Alignment Discovery

A common issue in PyTorch development is RuntimeError: Expected all tensors to be on the same device. This occurs when executing arithmetic or matrix operations on operands located on different devices (e.g. CPU vs. CUDA).

Torch-Candle intercepts binary operations and automatically detects cross-device operands. It identifies the primary execution device on-the-fly, migrates the secondary operands without manual developer intervention, and executes the operation seamlessly.

How it benefits LLM fine-tuning:

In Supervised Fine-Tuning pipelines, data loaders deliver input batches on host memory (CPU) while the model weights reside on accelerated cards (CUDA). Torch-Candle completely eliminates boilerplate .to(device) calls.

Zero-Allocation In-Place AdamW Optimizer

Optimizers like AdamW require storing momentum and velocity states for every parameter in the neural network. In PyTorch, computing weight updates creates dynamic allocations and intermediate buffers, raising Peak VRAM consumption.

Torch-Candle’s custom optimizer maps momentum and velocity tensors directly into the Rust backend's memory allocations. Update calculations are executed in-place (mutating states directly). This limits memory allocation peaks and keeps VRAM overhead to the absolute minimum.

Dynamic Graph JIT Compiler

Analogous to PyTorch’s torch.compile(), Torch-Candle utilizes a lightweight tracing compiler. During the initial forward pass, it traces functional subgraphs and maps tensor transformations as a static computation graph.

By mapping compile-time static paths down to the Candle Rust backend, the compiler eliminates standard Python interpretation overhead. It produces cached, vectorized execution pathways, delivering near-instant subsequent performance.

📝 Parity and Technical Gap Checklist

Tracking implementation maturity against standard PyTorch interfaces based on current codebase metrics

✓

Self-Healing Autograd (SHA) Engine

Fully operational inside Tensor.grad property. Intercepts element-wise NaN/Inf anomalies and applies EMA-based parameter reconstruction dynamically.

✓

Zero-Allocation In-Place AdamW Optimizer

Implemented under torch_candle.optim.AdamW. Mutates parameters, momentum vectors, and velocity states directly in-place to minimize peak VRAM spikes.

✓

Auto-Device Alignment Discovery

Integrated inside core arithmetic and tensor operation methods. Automatically converts and aligns device layouts without manual boilerplate code.

⚠

torch.utils.data Loaders (Basic Parity)

The codebase currently contains basic implementations in utils/data/dataloader.py and dataset.py. Supports collated stack yields, but lacks multi-process workers, pinning, and custom collate_fn overlays.

✗

Distributed & Multi-Node Training (torch.distributed / Hogwild)

Currently missing in Torch-Candle. Lacks NCCL/Gloo runtime bindings or shared tensor multiprocessing, limiting current deployments to single-device acceleration or localized fine-tuning.
